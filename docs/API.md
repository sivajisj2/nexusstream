# API and producer guide

The generated schema at `/api-docs/openapi.json` and Swagger UI at `/docs/` are the HTTP contract. Authenticate protected routes with `X-API-Key`. Both producer and operator actions currently use the same key.

## Event envelope

```json
{
  "events": [{
    "id": "7c5f5746-fd97-4da2-919d-0a1d06f97c2e",
    "source": "billing",
    "kind": "invoice.created",
    "payload": {"amount":2499,"currency":"INR"}
  }]
}
```

| Field | Rule |
|---|---|
| `events` | 1–100 events; duplicate IDs inside one batch rejected |
| `id` | Non-nil UUID generated by producer |
| `source`, `kind` | 1–128 ASCII letters/digits or `.`, `-`, `_`, `/` |
| `payload` | JSON object; serialized compact JSON at most 65,536 bytes |
| Body | At most 1,048,576 bytes total |

Unknown envelope fields are rejected. `received_at` is assigned by PostgreSQL on acceptance. Clients cannot supply it.

## Responses

| Status | Meaning | Producer action |
|---|---|---|
| 202 | Batch committed; receipt reports accepted and duplicates | Retain event IDs for audit |
| 400 | Invalid JSON, semantic validation, or invalid filters | Fix input |
| 401 | Missing/invalid API key | Correct credentials |
| 404 | Requested event does not exist | Check UUID |
| 409 | Existing ID has different content, or replay target is not dead | Investigate; do not blindly retry |
| 413 | Body exceeds 1 MiB | Reduce batch size |
| 415 | Unsupported/missing Content-Type on JSON input | Use application/json |
| 422 | JSON structure/type mismatch | Fix envelope shape |
| 503 | Database/storage unavailable | Retry same IDs with exponential backoff and jitter |

Application errors are JSON `{ "error": "..." }`. Axum extractor errors can be plain text; clients must inspect Content-Type before parsing an error response. Raw SQL errors and credentials are not returned to clients.

If a connection drops after sending, the commit result is unknown. Retry the exact batch with the same UUIDs. Never generate new IDs merely because a response was lost. Validation, duplicate-ID-in-batch, and content conflicts fail the whole batch.

## Explorer

`GET /v1/events?limit=25&before=123&source=billing&kind=invoice.created`

`limit` defaults to 25, maximum 100. `before` is a positive sequence cursor. Filters are exact matches and combine with AND. A response has `events` and nullable `next_cursor`. Pass `next_cursor` as `before` for an older page. Do not infer cursor values from UUIDs or timestamps. Refresh without a cursor for newest events.

## Replay

`POST /v1/events/{uuid}/replay` accepts no body. Only a dead delivery can be requeued. It resets attempts/error and makes the record immediately eligible. Returns 204 on success or 409 for a missing/non-dead delivery. The accepted event content remains immutable.

## Metrics

`GET /metrics` requires an API key and emits Prometheus gauges: `nexus_events_total`, `nexus_events_pending`, `nexus_events_done`, `nexus_events_dead`. These are database snapshots. They are not HTTP request counters or lifetime throughput measurements. Configure a Prometheus scrape header via a proxy or use a scraper capable of custom headers.
