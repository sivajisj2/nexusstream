# Operations

## Configuration

| Variable | Required | Default / behavior |
|---|---|---|
| DATABASE_URL | Yes | PostgreSQL connection URL; never logged deliberately |
| NEXUS_API_KEY | Yes | Minimum 32 bytes; generate randomly, keep out of Git |
| NEXUS_BIND | No | 127.0.0.1:8080; container binds 0.0.0.0:8080 |
| RUST_LOG | No | info; structured JSON logs |
| POSTGRES_PASSWORD | Compose | Generated by setup script |

Compose uses a durable named volume, health-gated startup, loopback ports, a non-root API process, read-only root filesystem, dropped capabilities, and a 30-second stop grace period. Migrations run before readiness. Avoid changing existing migration files once deployed; add a new migration instead.

## Deploying beyond localhost

Use a TLS reverse proxy with explicit request rate, concurrency, body-size, and response time limits. Restrict dashboard/docs to trusted operators. The current key grants both event publication and read/replay access; split producer and operator roles before granting untrusted producers access. Do not expose PostgreSQL to the internet. Add secret-manager injection, centralized redacted logs, disk monitoring, restore drills, and workload-specific admission limits.

The application has no baked-in TLS, tenant isolation, automatic key rotation, or application-level rate limiter. Those are explicit deployment requirements, not implicit guarantees. A browser with an active operator key can read all events. Do not ingest unnecessary credentials or personal data.

## Health and diagnostics

- `/healthz`: process alive; does not check the database.
- `/readyz`: database reachable; use for deployment readiness. It does not guarantee worker progress.
- `/v1/stats`: pending/dead count growth indicates stalled delivery.
- `/metrics`: protected database gauges for scraping.
- `docker compose logs -f api`: structured request/worker diagnostics.

A pending spike with database errors requires restoring PostgreSQL connectivity. Dead letters indicate repeated archive sink failure; investigate database constraints, disk space, privileges, and logs before replaying. The API intentionally does not expose raw SQL errors.

## Backup and restore

Back up events, deliveries, archive, and migration history together using PostgreSQL tooling. Example for a running local Compose stack:

```bash
mkdir -p backups
docker compose exec -T postgres pg_dump -U nexus -d nexus -Fc > backups/nexus.dump
```

Keep backups private and off-host. Test restore into a separate database before trusting a backup. A backup contains event payloads; apply the same access controls as the database. Restoring only one table can violate delivery guarantees.

## Shutdown and restart

`docker compose stop` sends SIGTERM. HTTP requests drain before worker shutdown; in-flight worker work either commits or rolls back. Restarting resumes pending records automatically. `docker compose down` leaves the named volume intact. Removing a volume destroys stored events, so volume deletion is not part of routine reset instructions.

## Retention

No automatic retention is implemented. Plan capacity and a retention policy before long-running use. Deleting events requires coordinated deletion of dependent delivery/archive rows and changes the lifetime of idempotency guarantees. Prefer an explicit maintenance migration or administrative job, reviewed for your requirements.
